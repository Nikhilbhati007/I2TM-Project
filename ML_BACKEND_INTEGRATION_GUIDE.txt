3.1 MODEL 1: 4-APPROACH TRAFFIC DENSITY DETECTOR
----------------------------------------------------------------------------------------------------
• File Location: `backend/ml/models/density_detector.py`
• FastAPI Route: `POST /api/ml/detect-density`
• Purpose: Calculates vehicle count, road occupancy %, and congestion level across 4 approaches (North, South, East, West).

• Expected Input Payload (JSON):
{
  "junction_id": "J-04",
  "approaches": {
    "North": { "vehicle_count": 42, "capacity": 50, "avg_speed_kmh": 18.2 },
    "South": { "vehicle_count": 21, "capacity": 50, "avg_speed_kmh": 34.0 },
    "East":  { "vehicle_count": 48, "capacity": 50, "avg_speed_kmh": 9.5 },
    "West":  { "vehicle_count": 12, "capacity": 50, "avg_speed_kmh": 42.1 }
  }
}

• Expected Output Response (JSON):
{
  "junction_id": "J-04",
  "total_vehicles": 123,
  "average_density_pct": 61.5,
  "critical_approaches": ["East", "North"],
  "approaches_evaluated": {
    "North": { "density_pct": 84.0, "status": "HIGH", "suggested_green_sec": 45 },
    "South": { "density_pct": 42.0, "status": "MEDIUM", "suggested_green_sec": 25 },
    "East":  { "density_pct": 96.0, "status": "CRITICAL", "suggested_green_sec": 60 },
    "West":  { "density_pct": 24.0, "status": "LOW", "suggested_green_sec": 15 }
  }
}

3.2 MODEL 2: RISKY DRIVING & LANE CUT/SWERVE AI TRAJECTORY INTERCEPTOR
----------------------------------------------------------------------------------------------------
• File Location: `backend/ml/models/risk_analyzer.py`
• FastAPI Route: `POST /api/ml/analyze-risk`
• Purpose: Evaluates vehicle centroid trajectory points [(x, y, timestamp)] for sudden swerving (>32°),
  abrupt multi-lane cuts, wrong-side driving, and generates a crash probability score (0-100%).

• Expected Input Payload (JSON):
{
  "vehicle_id": "DL-04-TC-201",
  "speed_kmh": 58.0,
  "trajectory": [
    { "x": 102.4, "y": 45.1, "timestamp": 1786700000.1 },
    { "x": 118.2, "y": 72.8, "timestamp": 1786700000.6 },
    { "x": 145.0, "y": 120.3, "timestamp": 1786700001.2 }
  ]
}

• Expected Output Response (JSON):
{
  "vehicle_id": "DL-04-TC-201",
  "risk_detected": true,
  "risk_score": 84.0,
  "pattern_type": "AGGRESSIVE_LANE_CUT",
  "alert_level": "CRITICAL",
  "swerve_angle_deg": 38.4,
  "recommended_action": "HOLD_UPSTREAM_SIGNAL_RED_AND_ALERT_MARSHAL",
  "reason": "Abrupt 38.4° deflection across 3 lanes at 58 km/h creates high T-bone collision risk."
}

3.3 MODEL 3: PATIENT-SEVERITY EMERGENCY TRIAGE & GREEN CORRIDOR ENGINE
----------------------------------------------------------------------------------------------------
• File Location: `backend/ml/models/triage_engine.py`
• FastAPI Route: `POST /api/ml/triage-emergency`
• Purpose: Computes green corridor pre-clear distance, signal hold duration, and roadside Variable Message Sign (VMS)
  countdown based on patient condition (CRITICAL / SERIOUS / STABLE) and vehicle type (Ambulance, Fire Engine, Police).

• Expected Input Payload (JSON):
{
  "ambulance_id": "DL-01-AMB-889",
  "patient_severity": "CRITICAL",
  "distance_to_junction_m": 850.0,
  "current_speed_kmh": 45.0,
  "route_congestion_pct": 88.0
}

• Expected Output Response (JSON):
{
  "ambulance_id": "DL-01-AMB-889",
  "triage_state": "RED",
  "priority_level": 1,
  "eta_seconds": 68.0,
  "clear_distance_meters": 1200,
  "signal_action": {
    "override_active": true,
    "target_approach": "EAST",
    "hold_conflicting_approaches": ["NORTH", "SOUTH", "WEST"],
    "allocated_green_seconds": 90
  },
  "roadside_display": {
    "message": "Keep left lane clear for emergency vehicle",
    "suggested_wait_seconds": 90
  }
}

3.4 MODEL 4: MULTI-JUNCTION ARTERIAL ROUTE CONGESTION PREDICTOR
----------------------------------------------------------------------------------------------------
• File Location: `backend/ml/models/route_predictor.py`
• FastAPI Route: `POST /api/ml/predict-route`
• Purpose: Models multi-node arterial networks (`J-01` -> `J-02` -> `J-03` -> `J-04`) to forecast transit ETA
  and bottleneck delays along an ambulance run to the destination hospital.

• Expected Input Payload (JSON):
{
  "corridor_id": "CORRIDOR-AIIMS",
  "junctions": [
    { "junction_id": "J-01", "current_density": 72.0, "distance_to_next_m": 400 },
    { "junction_id": "J-02", "current_density": 88.0, "distance_to_next_m": 600 },
    { "junction_id": "J-03", "current_density": 45.0, "distance_to_next_m": 500 }
  ]
}

• Expected Output Response (JSON):
{
  "corridor_id": "CORRIDOR-AIIMS",
  "total_distance_m": 1500,
  "predicted_transit_time_sec": 142.5,
  "bottleneck_junction": "J-02",
  "bottleneck_risk": "HIGH",
  "pre_clear_schedule": [
    { "junction_id": "J-01", "pre_clear_in_sec": 0, "hold_sec": 45 },
    { "junction_id": "J-02", "pre_clear_in_sec": 35, "hold_sec": 60 },
    { "junction_id": "J-03", "pre_clear_in_sec": 85, "hold_sec": 40 }
  ]
}

3.5 MODEL 5: DYNAMIC DENSITY-WEIGHTED SIGNAL PHASE OPTIMIZER
----------------------------------------------------------------------------------------------------
• File Location: `backend/ml/models/signal_optimizer.py`
• FastAPI Route: `POST /api/ml/optimize-signal`
• Purpose: Replaces fixed 60s timers by computing mathematical green splits proportional to queue sizes.

• Expected Input Payload (JSON):
{
  "approaches": {
    "North": { "density_pct": 84.0, "vehicle_count": 42 },
    "South": { "density_pct": 42.0, "vehicle_count": 21 },
    "East":  { "density_pct": 96.0, "vehicle_count": 48 },
    "West":  { "density_pct": 24.0, "vehicle_count": 12 }
  },
  "cycle_time_sec": 120,
  "emergency_override": false,
  "emergency_approach": "EAST"
}

• Expected Output Response (JSON):
{
  "cycle_time_sec": 120,
  "emergency_override_active": false,
  "phase_split": {
    "East":  { "green_sec": 46, "yellow_sec": 4, "red_sec": 70 },
    "North": { "green_sec": 40, "yellow_sec": 4, "red_sec": 76 },

4. NODE.JS WEB API INTEGRATION POINTS (backend/web/)
====================================================================================================
The Node.js Express server acts as the central middleware. If you want the Web Backend to proxy your ML calls:

1. `backend/web/server.js`:
   - Line 12: `const ML_SERVICE_URL = process.env.ML_SERVICE_URL || 'http://localhost:8000';`
   - Line 105: `app.post('/api/emergency/trigger', async (req, res) => ...)`
     Calls `${ML_SERVICE_URL}/api/ml/triage-emergency` via Axios and broadcasts the updated state over WebSockets (`wss`).

2. Adding new proxy endpoints in `server.js`:
   To forward live density detections or risk analysis from cameras to the web server:
   ```javascript
   app.post('/api/traffic/analyze-density', async (req, res) => {
     try {
       const response = await axios.post(`${ML_SERVICE_URL}/api/ml/detect-density`, req.body);
       activeSimulation.approaches = response.data.approaches_evaluated;
       broadcastState();
       res.json(response.data);
     } catch (err) {
       res.status(500).json({ error: err.message });
     }
   });
   ```

5. FRONTEND INTEGRATION POINTS & STATE HOOKS (frontend/src/)
====================================================================================================
The React frontend is fully reactive. Here is the exact mapping of where each ML model's data is displayed:

1. `frontend/src/context/TrafficContext.jsx` [PRIMARY STATE HUB]:
   - `approaches`: Holds 4-approach live density % (Updated by Model 1).
   - `emergency`: Holds triage level, countdown, vehicle type, and roadside message (Updated by Model 3).
   - `alerts`: Master alert list (Populated by Model 2 risky driving events & Model 1 congestion alerts).
   - `suggestions`: Holds 1-click dynamic signal adjustments (Generated by Model 5).

2. `frontend/src/components/dashboard/views/OverviewView.jsx`:
   - Visualizes junction density gauges, collision risk radar (84%), and emergency corridor status.

3. `frontend/src/components/dashboard/RiskPatternModule.jsx`:
   - Displays Model 2 outputs: Vehicle ID (`DL-04-TC-201`), crash probability (84%), swerve angle (38°), and marshal dispatch buttons.

4. `frontend/src/components/dashboard/GreenCorridorPanel.jsx`:
   - Dispatches emergency triage to Model 3 with vehicle selector (`Ambulance`, `Fire Engine`, `Police Patrol`).

5. `frontend/src/components/dashboard/RoadsideDisplayBoard.jsx`:
   - Displays Model 3 VMS countdown clock (`WAIT: 90s`) and driver instructions.

6. `frontend/src/components/dashboard/views/MapView.jsx`:
   - Displays Model 4 multi-junction route predictions, animated vehicle position, and color-coded congestion heat map.

7. `frontend/src/components/dashboard/views/ServicesView.jsx`:
   - Live telemetry inspector for all 5 ML models (Inference latency, accuracy %, active status).

----------------------------------------------------------------------------------------------------
Ensure the function signatures in `main.py` match your new model classes.
Example:
```python

@app.post("/api/ml/detect-density")

    return CustomYOLODetector.process_frame(request.dict())
```
